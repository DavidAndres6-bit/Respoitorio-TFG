RESUMEN TÉCNICO - insertarBBDD.py
==================================

1. CONEXIÓN A LA BASE DE DATOS
   - Nos conectamos a MySQL usando la librería mysql-connector-python, que es la
     librería oficial de MySQL y la más compatible con PythonAnywhere.
   - Los datos de conexión (host, usuario, contraseña y nombre de la base de datos)
     están centralizados en el diccionario DB_CONFIG al inicio del script, lo que
     facilita cambiarlos sin tocar el resto del código.
   - Si la conexión falla, el script informa del error y se detiene.

2. CARGA DE MATRÍCULAS EXISTENTES EN BASE DE DATOS
   - Antes de procesar ningún CSV, hacemos un SELECT de todas las matrículas que
     ya existen en la tabla vehiculos_cyl y las cargamos en un set de Python.
   - Usamos un set porque las búsquedas en un set son instantáneas (O(1)), lo que
     es fundamental cuando tenemos millones de registros.
   - Este set representa la "foto" del estado actual de la base de datos y es el
     que usamos para detectar qué es nuevo y qué ha desaparecido.

3. CONVERSIÓN DE FECHAS
   - Los campos FECHA_MATR y FECHA_ACTUALIZACION vienen en los CSVs con formato
     DD/MM/YYYY HH:MM:SS, pero MySQL espera DATE (YYYY-MM-DD) y DATETIME
     (YYYY-MM-DD HH:MM:SS) respectivamente.
   - La función convertir_fecha() acepta ambos formatos (con y sin hora) y los
     transforma al formato correcto antes de insertar. Si el valor es inválido
     o vacío, devuelve None para que MySQL lo almacene como NULL.

4. PROCESADO DE CADA CSV (procesar_csv)
   - Leemos cada uno de los 9 CSVs de provincia generados por procesarCSV.py.
   - Para cada fila del CSV tomamos una de estas decisiones:
     a) Si la matrícula YA está en el set de matrículas de BBDD → la saltamos,
        no insertamos nada (el registro ya existe y no ha cambiado).
     b) Si la matrícula NO está en el set → insertamos el registro completo
        en la tabla vehiculos_cyl con todos sus campos.
   - Acumulamos todas las matrículas del CSV en un set global (matriculas_csv_global)
     que usaremos al final para detectar bajas.
   - Usamos INSERT IGNORE en lugar de INSERT para que si por algún motivo una
     matrícula duplicada llega a la inserción, MySQL la descarte sin abortar el proceso.

5. DETECCIÓN Y MARCADO DE BAJAS (marcar_bajas)
   - Al terminar de procesar todos los CSVs, comparamos los dos sets:
       bajas = matriculas_bbdd - matriculas_csv_global
   - Esta operación de resta de conjuntos nos devuelve las matrículas que estaban
     en la base de datos pero no aparecen en ninguno de los CSVs de este mes.
   - Eso significa que esos vehículos ya no están en los datos de la DGT →
     los marcamos como Baja actualizando su campo ESTADO_ACTUAL a 'B'.
   - Lo hacemos con un único UPDATE con IN en lugar de un UPDATE por cada baja,
     lo que es mucho más eficiente cuando hay muchas bajas.

6. TRANSACCIÓN (commit y rollback)
   - Todas las operaciones (inserciones y actualizaciones de baja) se realizan
     dentro de una transacción.
   - Si todo va bien → commit() confirma todos los cambios en la base de datos.
   - Si algo falla en cualquier punto → rollback() deshace todos los cambios
     realizados en esa ejecución, dejando la base de datos en el estado anterior.
   - Esto garantiza que nunca quedará la base de datos a medias — o se completa
     todo el proceso o no se guarda nada.
   - El bloque finally cierra siempre la conexión, haya habido error o no.

7. PARAMETRIZABLE MES A MES
   - El script está diseñado para ejecutarse mensualmente de forma segura.
   - La primera vez que se ejecuta inserta todos los registros.
   - Las siguientes veces solo inserta los vehículos nuevos, ignora los que ya
     existen y marca como baja los que han desaparecido de los datos de la DGT.
   - Esto lo conseguimos gracias a la comparación de sets entre las matrículas
     de la base de datos y las matrículas de los CSVs del mes actual.

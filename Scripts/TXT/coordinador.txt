RESUMEN TÉCNICO - coordinador.py
==================================

1. PROPÓSITO
   - El coordinador es el script maestro que orquesta todo el proceso de descarga,
     procesamiento e inserción en base de datos con un solo comando.
   - Importa y ejecuta en orden los cuatro scripts del proyecto:
       1. descarga.py      → descarga el ZIP más reciente de la DGT
       2. procesarTXT.py   → extrae los TXT de CyL del ZIP
       3. procesarCSV.py   → procesa los TXT y genera los CSVs con matrículas
       4. insertarBBDD.py  → inserta los CSVs en la base de datos MySQL
   - Los cuatro scripts son un todo — no tienen sentido unos sin los otros,
     por lo que si cualquiera falla el coordinador se detiene inmediatamente.

2. CONTROL DE ERRORES (ejecutar_paso)
   - Cada script se ejecuta dentro de un bloque try/except que captura cualquier
     error que pueda producirse.
   - Si un paso falla, el coordinador informa del nombre del paso y del error,
     y detiene el proceso con sys.exit(1).
   - El código de salida 1 indica error en sistemas Unix/Linux — PythonAnywhere
     lo interpreta para saber si la tarea terminó bien o mal.
   - El código de salida 0 indica éxito.

3. EJECUCIÓN AUTOMÁTICA MENSUAL
   - El coordinador está diseñado para ejecutarse como tarea diaria en PythonAnywhere,
     pero solo actúa los días indicados en DIAS_EJECUCION (actualmente días 5 y 20).
   - Cada día que se ejecuta comprueba si hoy es uno de esos días. Si no lo es,
     informa por pantalla y sale sin hacer nada (sys.exit(0) → salida limpia sin error).
   - Elegimos los días 5 y 20 porque la DGT suele publicar los datos a mediados de mes,
     y así tenemos dos oportunidades de recoger los datos más recientes.
   - Para cambiar los días de ejecución basta con modificar la constante DIAS_EJECUCION
     al inicio del script, sin tocar nada más.

4. EL PARÁMETRO --forzar
   - El control de días es necesario para la ejecución automática, pero supone un
     problema cuando queremos ejecutar el coordinador manualmente fuera de esos días
     (por ejemplo para hacer pruebas o para una ejecución puntual).
   - Para resolverlo, el script acepta el argumento --forzar desde la línea de comandos:
         python coordinador.py --forzar
   - Cuando se pasa --forzar, el script ignora la comprobación del día y ejecuta
     el proceso completo independientemente de la fecha.
   - Técnicamente funciona así: sys.argv es una lista que contiene los argumentos
     pasados al script. Si '--forzar' está en esa lista, la comprobación del día
     se omite. Si no está, la comprobación se aplica normalmente.
   - La tarea programada de PythonAnywhere llama al script sin --forzar, por lo que
     respeta siempre el control de días. Solo nosotros, al ejecutarlo manualmente
     desde la consola, usamos --forzar cuando lo necesitamos.

5. CONFIGURACIÓN EN PYTHONANYWHERE
   - En la pestaña Tasks de PythonAnywhere configuramos una tarea diaria con el comando:
         python /home/DJF/scripts/coordinador.py
   - La hora recomendada es de madrugada (ej: 03:00) para no interferir con otros procesos.
   - PythonAnywhere ejecutará el script cada día, pero gracias al control de DIAS_EJECUCION
     solo procesará datos los días 5 y 20 de cada mes.
